# Completion — Make SanoPOS Actually Connect

> The "finish the software" effort: get every surface wired end-to-end (no broken buttons / dead routes / unresolved flags / contract mismatches), close the real Square feature gaps, and polish the rough edges — **mode by mode, one plan at a time.**

## What's here

| File | Purpose |
|---|---|
| [completion-spec.md](completion-spec.md) | Authoritative spec — scope, how plans are cut, the two-phase workflow, autonomy, guardrails. **Read first.** |
| [completion-prompt.md](completion-prompt.md) | Two paste-in Fable 5 kickoffs — **Prompt A** generates the plans, **Prompt B** executes one. |
| [prompts-per-plan.md](prompts-per-plan.md) | Ready-to-paste execution prompt for **each** plan, with the Fable-vs-Opus call + decisions baked in, and the recommended run order. |
| [plan-template.md](plan-template.md) | The exact shape every plan file follows. |
| `plans/` | Where the generated plan files land (`00-core-spine.md`, `01-cross-surface.md`, one per mode, …). Empty until Prompt A runs. |

## How to run it

1. Open a fresh Fable 5 session (`claude-fable-5`). Paste **Prompt A** → Fable audits from code and writes the plan files + fills the register below, then **stops for your approval**.
2. Review the cut and the register. Approve or adjust.
3. For each plan, open a session and paste **Prompt B** with that plan's filename → Fable executes it (P0 wiring → P1 gaps → P2 polish), verifies live, updates the register.

**Why this cut (deltas from the §3 seed):**
- `commissions` merged into `03-appointments` — it's one flag (`phase2_commissions`) enabled by exactly one preset (salon), and every commission flow is walked with the same salon tenant as the bookings checklist. A standalone plan would duplicate tenant + walkthrough for ~6 rows.
- Clinical presets (dental/vet/physio) and gym/photography carry two modes each; they're split by *surface*, not preset: booking surface → 03, clinical stack → 08, memberships → 10, projects → 09. Each plan's preset-skin checklist marks which half it owns, so nothing is double-fixed.
- Growth kept as a single plan (11): its items share the storefront/marketing/gateway substrate and are mostly P1 build work with one confirmed P0 (marketplace sync worker stub).
- Sequencing kept core-first: 00 → 01 → then modes ordered by tenant impact (restaurant and appointments cover the most presets; wholesale is the market wedge; the four §10 exceeds-Square verticals are wiring-proof plans and can run in any order; growth last since it's build-heavy and redesign-entangled).

## Task 1: Fix Signup Auth State (Item #1)

**Files:**
- Modify: `frontend/src/auth/AuthProvider.jsx` (around line 322)

**Context:**
`AuthProvider` patches `window.fetch` globally. Around line 322 it skips injection when `!employee?.id`. But a super-admin IS an employee — so when they navigate to `/signup`, the interceptor injects their Bearer token, causing the backend's `loadTenantAndPerms` middleware to reject the request with 403.

**The fix:** Add a URL-based exclusion for public auth endpoints before the employee ID check.

**Step 1: Find the injection guard**

The relevant block is around line 322 in `AuthProvider.jsx`:
```js
if (!isApiCall || !employee?.id) {
  return nativeFetch(input, init);
}
```

**Step 2: Add public-endpoint exclusion**

Edit that block to also skip injection for public auth paths:
```js
// Public endpoints that must never receive auth headers
const PUBLIC_PATHS = ["/api/auth/signup", "/api/auth/login", "/api/auth/mt-login",
  "/api/auth/forgot-password", "/api/auth/reset-password", "/api/auth/refresh"];
const urlStr = typeof input === "string" ? input : input.url;
const isPublicAuth = PUBLIC_PATHS.some(p => urlStr.includes(p));

if (!isApiCall || !employee?.id || isPublicAuth) {
  return nativeFetch(input, init);
}
```

**Step 3: Test manually**
- Log in as super-admin at `/admin`
- Open a new tab and navigate to `/signup`
- Fill in the form and submit — should succeed (no 403)
- Check browser DevTools Network tab: `POST /api/auth/signup` should have NO `Authorization` header

**Step 4: Commit**
```bash

git commit -m "fix: exclude public auth endpoints from fetch interceptor token injection"
```

## Task 2: Tenant Feature-Usage Analytics — Backend (Item #5)

**Files:**
- Modify: `backend/routes/admin.js`

**Context:**
Each tenant has an `action_history` table in their schema (`tenant_<slug>.action_history`) with columns: `id, user_name, action_type, description, timestamp`. We want to aggregate counts per `action_type` to show admins which features each tenant actually uses.

The existing stats endpoint at `GET /api/admin/tenants/:id/stats` (around line 380 in admin.js) is a good pattern to follow — it queries `tenant_${tenant.slug}` schema directly.

**Step 1: Add the endpoint to admin.js**

Find the section with tenant stats endpoints (search for `tenants/:id/stats`) and add a new endpoint right after it:

```js
// ── Feature Usage ──────────────────────────────────────────────────────────
app.get("/api/admin/tenants/:id/feature-usage", requireSuperAdmin, async (req, res) => {
  try {
    const { rows: [tenant] } = await masterDb.query(
      "SELECT slug FROM tenants WHERE id = $1 AND deleted_at IS NULL", [req.params.id]
    );
    if (!tenant) return res.status(404).json({ error: "Tenant not found" });

    const s = `tenant_${tenant.slug}`;

    // Action type counts (all time + last 30 days)
    const { rows: allTime } = await db.pool.query(
      `SELECT action_type, COUNT(*) AS total
       FROM ${s}.action_history
       GROUP BY action_type
       ORDER BY total DESC`
    );

    const { rows: last30 } = await db.pool.query(
      `SELECT action_type, COUNT(*) AS total
       FROM ${s}.action_history
       WHERE timestamp >= NOW() - INTERVAL '30 days'
       GROUP BY action_type
       ORDER BY total DESC`
    );

    // Most active users
    const { rows: topUsers } = await db.pool.query(
      `SELECT user_name, COUNT(*) AS actions
       FROM ${s}.action_history
       WHERE timestamp >= NOW() - INTERVAL '30 days'
         AND user_name IS NOT NULL
       GROUP BY user_name
       ORDER BY actions DESC
       LIMIT 5`
    );

    res.json({ all_time: allTime, last_30_days: last30, top_users: topUsers });
  } catch (err) {
    console.error(err);
    res.status(500).json({ error: "Failed to load feature usage" });
  }
});
```

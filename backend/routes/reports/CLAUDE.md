# backend/routes/reports/

Report endpoints for `/api/reports/*`. All files export a factory of the form `(app, deps, helpers) => {...}` (some also return an object of reusable functions, noted below). Almost all routes return JSON — CSV conversion for exports happens client-side, except scheduled-report delivery (see `governance.js`) which builds CSV server-side.

Most routes have **no permission/feature guard** — they rely on the tenant middleware chain already having authenticated the request. Guards are called out explicitly below where they exist; assume none otherwise.

## Files

**`purchasing.js`** — `registerPurchasingReports`. Total/itemwise purchases, PO workflow (approval + payment state via CTEs), PO report, procurement parity (UNIONs receipts/transfers/adjustments, `LIMIT 1000`). Uses a manual `?`→`$N` placeholder rewrite instead of the shared `pgWhere` helper — watch parameter ordering if extending.

**`shifts.js`** — Cash-shift reports: cash-flow (date range), cash-audit/shift-summary/shift-sales/payment-summary/current-session-zreport (all **require `session_id`**, 400/404 if missing/not found), all-denominations (session_id optional). Shared `loadShift(shiftId)` helper joins shift + employee/outlet.

**`multichannel.js`** — `registerMultichannelReports`. Cross-channel (POS/Shopify/WooCommerce) summary, daily trend, top products. **Date params are `from`/`to`, not `date_from`/`date_to`.** Web-channel data comes from `web_orders`/`web_order_items`; merging with POS happens in JS via keyed Maps, not SQL UNION.

**`governance.js`** — Scheduled report exports + saved views. Mutation routes gated by `requirePerm("manage_employees")` + `requireFeature("reports_scheduled_exports")`; saved-view reads by `requireAnyPerm(["view_reports","manage_employees"])` + same flag. Returns `{ processPendingReportSchedules }` consumed by the worker/index wiring. `runSingleSchedule()` supports report keys `profit-by-product`, `stock-aging`, `stockout-risk`, `eod-digest` (builds an HTML digest and sends via nodemailer directly, not `services/email.js`), and `builder:<id>` (loads `custom_report_definitions`, delegates to `report-builder.js:buildQuery()`). CSV generation + R2 upload lives here, not per-report-module.

**`staff.js`** — Labor performance, loss-prevention (void/refund risk ratio per employee), labor-vs-sales (uses `employees.hourly_rate`), staff-attribution. Default 30-day lookback if `date_from` omitted. Multiple independently-numbered WHERE-param arrays concatenated in sequence — easy to break param ordering when extending.

**`clinical.js`** — `registerClinicalReports`. Imports `feature-flags`/`permissions` middleware directly, not via `deps`. All routes gated `[requireFeature("phase4_treatment_plans"), requirePerm("view_reports")]`. Plan completion, session attendance/no-show, revenue-per-plan, patient-retention (cohort CTE), lab-turnaround.

**`kds-analytics.js`** — `registerKdsAnalyticsRoutes`. Gated `[requireMode("restaurant"), requireFeature("phase4_restaurant_kds_analytics"), requirePerm("view_reports")]`. Prep-time percentiles (p50/p95 via `PERCENTILE_CONT`) by station/category. Date params are `from`/`to`.

**`menu-engineering.js`** — `registerMenuEngineeringReport`. Validates query via Zod (`schemas/menu-engineering`). Gated `[requireMode("restaurant"), requireFeature("phase4_restaurant_menu_engineering"), requirePerm("view_reports")]`. Boston Matrix classification (star/plowhorse/puzzle/dog) from popularity vs. margin, medians computed in JS. Voided lines contribute 0 to popularity/profit; comped/discounted lines count toward popularity but subtract the comp amount — driven by `sale_item_adjustments`.

**`stock-aging.js`** — `registerStockAgingReport`. Gated `requireAnyPerm(["view_reports","manage_inventory"])`. Age computed from most recent GRN `received_at` via `LATERAL` join (products with no GRN history default to `age_days = 0`). Buckets: fresh ≤30d, aging ≤60d, old ≤90d, critical >90d. **Gotcha: a duplicate, ungated `/api/reports/stock-aging` route also exists in `inventory.js`** (that one gated behind `reports_inventory_health_plus`) — Express route registration order in `reports/index.js` determines which actually serves the request; verify before assuming this one wins.

**`fbr-export.js`** — Gated `requirePerm("all_access")`. `from`/`to` are **required** (400 if missing). Reads the frozen per-line tax snapshot columns (`sale_items.tax_rate_at_sale`, `tax_amount_at_sale`, `hs_code_at_sale`) — explicitly never recomputes against live tax rates/products. Returns `{ rows, company }`; frontend does the CSV conversion.

**`analytics.js`** — Comparative trends, heatmaps, revenue-leaks (confirmed ungated), product-mix (basket co-occurrence), retail BCG matrix (dynamic thresholds computed first), customer RFM/details/retention/capture-rate, discount-leakage (gated `reports_profit_layer`), exceptions (gated `reports_exceptions`, `type` param selects negative-margin/high-discount/frequent-voids/frequent-returns), outlet-comparison (accepts both `from/to` and `date_from/date_to`), supplier-wise, returns-by-reason (date params required, no fallback).

**`sales.js`** — Largest file (~1500 lines). Top-salespeople, sales-summary (tax-by-rate wrapped in try/catch for pre-v83 deploys missing `tax_rate_at_sale`), sales-detail/order-wise (search param), monthly-mop-matrix, category/subcategory-wise, item-wise (Swagger doc says `from`/`to` but code actually reads `date_from`/`date_to` — **doc/code param mismatch**), brand-wise, customer-wise (no date filter), product-performance, performance-workspace (5 parallel queries via `Promise.all`), performance-comparison (fragile manual `$N` offsetting across nested subqueries — flagged in file comments), refunds-voids, cashier-wise (3 independent CTEs chained via `pgWhere(..., startIdx)`), profit-summary/profit-by-product/profit-by-outlet (all gated `reports_profit_layer`). `applySaleTimeFilters` adds `time_from`/`time_to` (time-of-day, distinct from date range) on several routes. Heavy tz-safety handling — Postgres requires identical SELECT/GROUP BY expression text, so inline-literal tz strings are validated via `isValidTz` first.

**`finance.js`** — `registerFinanceReports`. Settlement overview, payables/receivables, AR aging (`as_of` validated against `YYYY-MM-DD` regex; bucket config from `req.company.ar_aging_buckets`, falls back to [30,60,90]), supplier-payments-invoices (`status=open` means `<> 'paid'`), finance-payment-mix, GST output (line-level, `LIMIT 500`), GST type summary (output vs input tax, net payable). Has its own local `pgify()` (parallel reimplementation of `helpers.pgWhere`) and `applyRangeFilters()` with a `columnType: "local"` option for non-UTC date columns (`expenses.expense_date`, `grn.received_at`).

**`dashboard.js`** — Single huge payload (`GET /api/reports/dashboard`, ~15 queries: zReport, today/yesterday scalars, profit metrics, expenses, month sales/purchases/refunds, top products/categories, hourly + 6-month trend, inventory status, per-outlet operational readiness looped per outlet (N+1), onboarding-checklist signals each wrapped in try/catch for schema tolerance, staff-of-day, cash position). Plus `GET /api/reports/dashboard/wholesale` (A/R outstanding/overdue, top buyers). Local `buildOutletClause(col, ids, startIdx)` builds `$N`-indexed fragments with manual index bookkeeping across ~15 queries — easy to break param count when adding a subquery.

**`inventory.js`** — Returns `{ buildForecastRows }` (reused by `replenishment-smart`). Sales-stock, inventory-dump (Swagger-documented; `aggregate=1` groups across outlets; `anomaly` filter for zero-stock/negative-stock/low-stock/zero-price/zero-cost/cost-over-sale/margin-risk), product-spec, on-hand (same aggregate/anomaly pattern), inventory-loss, wastage, replenishment, pricing-exceptions, pricing-margin, dead-stock (`inactive_days`, default 90), forecast-demand, replenishment-smart (gated `reports_inventory_health_plus`), **stock-aging** (gated `reports_inventory_health_plus` — the shadow-duplicate of `stock-aging.js` mentioned above), stockout-risk (gated `reports_inventory_health_plus`), product-movement, str-report, grn-report, history-cost, history-sale, product-audit (schema hygiene checks, 3 independently-numbered param groups combined via a sequential index counter), shrinkage (full balance-equation report — opening/expected/actual/variance across sales/returns/scrapped/GRN/adjustments/transfers; distinguishes "restocked" returns `restock_flag IS NOT FALSE` from "scrapped" `restock_flag = FALSE` as separate shrink vectors).

## Conventions / gotchas to know before touching this directory

- Date param naming is **not consistent** across files: most use `date_from`/`date_to`, but `multichannel.js` and `kds-analytics.js` use `from`/`to`, and `outlet-comparison` in `analytics.js` accepts both.
- Two duplicate/shadow `stock-aging` routes exist (`stock-aging.js` ungated, `inventory.js` gated) — check route registration order before assuming behavior.
- Several files reimplement the same param-building pattern independently (`pgify()` in `finance.js` vs. shared `helpers.pgWhere`) rather than sharing one utility — don't assume consistency when reading unfamiliar routes.
- `governance.js` is the only file that does CSV generation + R2 upload + direct nodemailer sending; other report routes are pure read/JSON.

# Middleware — Claude Guide

- **8 files** — Express middleware, mounted in specific order (see backend/CLAUDE.md Middleware Chain)
- **`tenant-auth.js`** — requires `init(deps)` at boot. Exports 6 functions: `loadEmployeePerms` (header-based, no JWT), `loadTenantAndPerms` → `resolveTenant` → `loadCompanyProfile` (5-min cache) → `resolveContext`. In MT mode, `dbProxy` uses AsyncLocalStorage for transparent tenant schema routing. `loadTenantAndPerms` also handles: token revocation (checks `revoked_tokens` table via jti + per-employee `tokens_revoked_before`), impersonation (appends "(impersonated by Super-Admin)" to name), kiosk scope restriction (only `/api/attendance/pin-*` + `/api/auth/*`), outlet context from JWT `oid` claim, 1-retry with 100ms delay on permission load failure. `resolveTenant` returns specific error codes: `TENANT_NOT_FOUND`, `TENANT_SUSPENDED`, `TENANT_DELETED`
- **`permissions.js`** — `requirePerm(perm)`, `requireAnyPerm(perms[])`, `requireContextOutlet`. `"all_access"` is superuser — bypasses all checks. `PERMISSION_RULES` array for declarative route guards. `ensureDefaultRolePermissions(db)` bootstraps roles
- **`feature-flags.js`** — requires `init(deps)` at boot. `requireFeature(flagKey)` returns 503 if off. `getFeatureFlagsMap(tenantId)` merges DB overrides with `DEFAULT_FEATURE_FLAGS` (60s cache). If `feature_flags` table missing, returns all defaults. Also exports: `invalidateFeatureFlagCache(tenantId)` — called by admin PUT to bust cache immediately; `createNotification(type, title, message, link)` and `notifyLowStockForSale(cartItems, outletId)` — notification helpers live here (not in a separate service)
- **`plan-limits.js`** — `requirePlanLimit(resource)`, `requireActiveSubscription`, `PLAN_DEFAULTS` for `"employees"`, `"outlets"`, `"products"`. `0` = unlimited. Only active in MT mode. Reads limit from master `tenants` table, counts from tenant DB. **Gotcha**: `requireActiveSubscription` uses `.then()` (not `await`) — subscription check is async while `next()` fires synchronously; works in practice but be aware of the pattern
- **`rate-limit.js`** — 4 limiters: `globalLimiter` (600/min, skips POS burst paths: `/api/sales`, `/api/products/search`, `/api/products/scan/`, `/api/orders`), `authLimiter` (20/15min), `webhookLimiter` (120/min), `reviewLimiter` (5/15min). Returns 429 with `Retry-After` header + `retry_after_seconds` in body. All limits configurable via env vars (`RATE_LIMIT_WINDOW_MS`, `RATE_LIMIT_GLOBAL_MAX`, `RATE_LIMIT_AUTH_MAX`, `RATE_LIMIT_WEBHOOK_MAX`). authLimiter and reviewLimiter skip in test mode
- **`validate.js`** — `validate(schema)` factory for Zod. Replaces `req.body` with parsed result. Returns 400 `{ error, details[] }` on failure
- **`upload-validation.js`** — `imageFileFilter`, `safeExtension()`, `ALLOWED_IMAGE_MIMES`, `ALLOWED_IMAGE_EXTS` for multer. Checks both MIME and extension. Allowed: JPEG, PNG, GIF, WebP, SVG, BMP, TIFF
- **`request-id.js`** — pino-http middleware. Generates/honours `X-Request-Id`. `req.log` available after this. Exports `enrichReqLog` to re-enrich `req.log` with tenant/employee context after auth. Logs warn for 4xx or slow (>2s), error for 5xx

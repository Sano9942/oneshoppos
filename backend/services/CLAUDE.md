# Services — Claude Guide

- **37 files** — core business services, all imported by route handlers via `deps` or direct `require()`
- **`crypto.js`** — AES-256-GCM encryption. Exports: `encryptSecret`, `decryptSecret`, `maskSecret`. Env: `INTEGRATION_SECRET_KEY` (falls back to `SHOPIFY_SECRET_KEY`). Key input: 64-char hex → raw bytes; 32-byte base64 → decoded; anything else → SHA-256 hashed
- **`email.js`** — unified `sendEmail()` (immediate via Resend — no SMTP path in this service) + `enqueueEmail()` (pg-boss queue, 3 retries × 60s). Also exports `resolveFrom()`. Tenant emails from `slug@sanopos.com`, platform from `noreply@sanopos.com`. **Gotcha**: `enqueueEmail`'s `db` param is accepted but completely ignored — email always enqueues to public schema pg-boss regardless of which DB is passed
- **`email-templates.js`** — `TEMPLATES` registry maps email type → `{ subject, html }` builder. `wrapEmailHtml(title, body)` renders branded shell. To add a new email type, add here AND register in `TEMPLATES`
- **`boss.js`** — pg-boss singleton factory: `getBoss()` (lazy-init, promise-deduplicated), `shutdownBoss()`. Throws if `DATABASE_URL` unset. Two-stage cleanup: completed jobs archived after 24h → deleted after 7 days (not a single "prune at 7 days")
- **`fbr.js`** — FBR Digital Invoicing. Exports: `buildInvoicePayload`, `buildCreditNotePayload` (returns), `buildDebitNotePayload` (voids), `postToFbr`, `enqueueFbrInvoice`, `validateConnection`, `getNextRetryDelay`, `FBR_URLS`, `BACKOFF_DELAYS`. `enqueueFbrInvoice`: DB row first, then pg-boss fire-and-forget. Exponential backoff: 60s→5m→15m→1h→4h
- **`payment-gateway.js`** — adapter pattern: `createCheckout()`, `createInvoiceCheckout()`, `verifyWebhook()`, `isEnabled()`, `refund()`, `processInlinePayment()`, `tokenize()`, `chargeSavedInstrument()`, `getPaymentAdapter()`, `BasePaymentAdapter`, `ADAPTERS` (keys: `manual`, `xpay`, `sandbox`). Default mode is `"manual"` (throws on `createCheckout`). Gate payment UI behind `isEnabled()`. Env: `XPAY_API_KEY`, `XPAY_WEBHOOK_SECRET`. **Gotcha**: `isEnabled()` checks `!!process.env.XPAY_API_KEY` — the `PAYMENT_GATEWAY` env var selects the adapter but `isEnabled()` depends on the API key being present, not just the var being set
- **`alerting.js`** — in-memory sliding-window alerts: `recordError`, `recordDbPressure`, `recordHealthCheckFailure`. Sends to `ALERT_EMAIL`. State resets on restart (by design)
- **`printer.js`** — factory: `makePrinterService(db)` → `{ printReceipt, printerStatus, printTest, printToNetwork }`. Supports USB and TCP. Printer-builder timeout: 3s; TCP status-ping timeout: 2s; `printToNetwork` raw socket timeout: 5s. Paper width from DB drives layout
- **`catalog-scheduler.js`** — `applyScheduledChange(db, change)`. Called by `boot/workers.js` scheduled-catalog worker per pending row. Validates `entity_type` + `field_name` against allowlist imported from `schemas/scheduled-changes.js` (defense in depth: route validates on write, service re-validates on apply), then runs target UPDATE + status update inside one `db.transaction()`. Non-throwing — returns `{status, reason}` so caller can loop over many rows without one bad row killing the batch. Security-critical: column name is interpolated into the UPDATE string, allowlist is the only thing preventing SQL injection
- **`logger.js`** — Pino singleton. `LOG_LEVEL` env var. Use `.child({ component })` for sub-loggers. Never create multiple instances
- **`contracts.js`** — contract lifecycle: `createContract`, `updateContract`, `sendContract`, `signContract`, `getContract`, `logContractEvent`. Tables: `contracts`, `contract_templates`, `contract_signers`, `contract_events`. Supports project-linked contracts and multi-signer flows
- **`projects.js`** — service project lifecycle: `createProject`, `updateProject`, `getProject`, `listProjects`, `createMilestone`, `updateMilestone`, `approveQuotation`, `convertQuotationToProject`, `logActivity`. Tables: `service_projects`, `project_milestones`, `project_activities` (not `project_activity_log`), `project_files`
- **`subscriptions.js`** — recurring subscription lifecycle: `computeNextPeriod`, `processRenewal`, `cancelSubscription`, `pauseSubscription`, `resumeSubscription`. Enqueues renewal jobs via pg-boss. Tables: `customer_subscriptions`, `subscription_runs`. `processRenewal` requires `tenantSlug` (throws if omitted). `boss.send` intentionally runs outside the transaction. Renewal jobs use `singletonKey` (`${subscriptionId}:${date}`) to deduplicate in pg-boss. INTERVAL_DAYS: monthly=30, quarterly=90, yearly=365 (not calendar year)
- **`customer-invoicing.js`** — B2B invoice lifecycle: `generateInvoiceNumber` (INV-000001 format), `computeInvoiceTotals` (pure), `recomputeBalance`, `convertQuotationToInvoice`, `createBatchInvoices`, `scheduleReminders`. Tables: `customer_invoices`, `customer_invoice_reminders`. `scheduleReminders` requires `tenantSlug` (throws if omitted). `createBatchInvoices` has 24h idempotency guard (same customer+due_date+total skips)
- **`project-billing.js`** — links invoices/subscriptions to projects: `attachInvoiceToProject`, `getProjectBillingSummary`. Delegates activity logging to `projects.js`
- **`allocation.js`** — fulfillment allocation: `allocateOrder`, `getAllocationsForOrder`. Pickup → fixed outlet; ship-to-customer → highest-stock outlet. Table: `web_order_allocations`. Runs inside `db.transaction()`. **No partial fulfillment**: outlet must have full requested quantity — if no single outlet qualifies, throws 400
- **`quote.js`** — storefront pricing engine: `calculateQuote`, `resolvePriceForContext` (exported — price-list cascade: outlet→channel→customer→customer_group→customer.price_list_id (direct)→base). `calculateQuote` also evaluates active promotions (returns `appliedPromotions` + `discountTotal`) and accepts `courierId` for flat shipping rate lookup. Called before order creation
- **`reservation.js`** — inventory reservation for omnichannel: `createReservation`, `convertReservations`, `releaseReservations`, `expireStaleReservations`, `getActiveReservationsForOutlet`. Uses `SELECT ... FOR UPDATE` on `outlet_stock` to prevent oversell. Restores stock on release/expiry. Default TTL: 15 minutes. `releaseReservations` sorts stock keys before locking to prevent deadlocks
- **`storefront-cart.js`** — anonymous/authenticated cart for omnichannel storefront: `getOrCreateCart`, `addItem`, `updateItem`, `removeItem`, `getCartWithItems`. Table: `storefront_carts`. Cart expires after 7 days. `addItem` upserts — same product+variant increments quantity rather than adding a duplicate line
- **`public-tenant-context.js`** — shared public tenant resolver (extracted from storefront): `resolvePublicTenantDb(req, deps)`. Used by storefront, QR ordering, and public booking routes. MT-aware (reads `tenant` query param or `x-tenant-slug` header)
- **`marketing.js`** — campaign audience resolution + delivery: `resolveAudience` (filter rules → customer IDs, also accepts `previewOnly` option → returns count+sample instead of full list), `enqueueCampaignSend` (requires `tenantSlug`). Reads `marketing_templates`, `marketing_campaign_audiences`. Filter types: group, tag, loyalty_tier, city, birth_month, last_purchase_days, min_spend, max_spend, has_email, has_mobile
- **`messaging.js`** — generic messaging inbox: `findOrCreateThread`, `addMessage`. Tables: `message_threads`, `message_entries`. Auto-resolves customer from WhatsApp mobile number. `addMessage` hardcodes `status='delivered'`; inbound messages increment `unread_count`, outbound replies reset it to 0
- **`sms.js`** — SMS delivery via adapter pattern. Exports: `sendSms`, `testProvider`, `getSmsAdapter`, `resolveProvider`, `BaseSmsAdapter`, `ADAPTERS`. Concrete adapters: `GenericHttpAdapter` (keys: `generic`, `zong_sms`, `jazz_sms`) + `TwilioAdapter`. Config via `integration_settings` (category `'sms'` or `'messaging_sms'`). `sendSms` persists to `sms_provider_messages` table (migration v24)
- **`approval-policy.js`** — policy evaluation: `evaluatePolicy`, `recordApprovalEvent`. Action types: `manual_discount`, `discount_code`, `return`, `unverified_return`, `void`, `tax_edit`, `order_cancel`, `custom_sale`. Called by `routes/approval-policies.js`
- **`restaurant-checks.js`** — restaurant check lifecycle. Exports: `createRestaurantCheck`, `getOpenChecks`, `assignSeat`, `splitCheckByItem`, `splitCheckBySeat`, `fireCourse`, `openTab`, `closeTab`, `recalcCheckTotals`. Uses `draft_orders` with `order_context != 'retail'`. QR public tokens for dine_in/bar contexts. Note: `addItemToCheck` and `closeCheck` do NOT exist — those names appeared in early design docs
- **`restaurant-floor.js`** — floor plan + table session service. Exports: `getFloorPlans`, `getFloorPlanWithTables`, `createFloorPlan`, `updateFloorPlan`, `openTableSession`, `updateTableSession`. Tables: `restaurant_floor_plans`, `restaurant_floor_sections`, `restaurant_tables`. Note: `createTableSession`/`closeTableSession` do NOT exist — closing is done via `updateTableSession({ status: "closed" })`
- **`restaurant-kds.js`** — Kitchen Display System: `getStations`, `createStation`, `updateStation`, `sendToKitchen`, `getTickets`, `bumpTicket`, `recallTicket` (resets bumped ticket back to `'new'`). Tables: `kds_stations`, `kds_tickets`, `kds_ticket_items` (junction, migration v29), `kds_station_routes` (item-to-station routing by category)
- **`booking-services.js`** — appointment CRUD: `createAppointment`, `rescheduleAppointment`, `cancelAppointment`. Checks overlap via `booking-availability.js`. Auto-sets status to `'pending'` if service `requires_confirmation`. `createAppointment` auto-schedules a 1-hour-before reminder in `appointment_reminders`. `source` param defaults to `'admin'`; admin bookings bypass time guards. `'public'` adds a 15-min minimum notice guard + `max_advance_days` limit (default 90), changes confirmation behavior, and enqueues a `booking_confirmation` email (non-fatal, only if `options.tenant` is passed)
- **`booking-availability.js`** — slot availability engine: `getAvailableSlots`, `checkOverlap`. Reads staff schedules + existing appointments. Tables: `booking_services`, `booking_staff_assignments`, `booking_availability_rules`, `appointment_blocks`. Slot granularity is hardcoded to 15-minute increments
- **`booking-reminders.js`** — reminder scheduler: `processPendingReminders(db, boss)`. Polls `appointment_reminders` where `status='pending'` and `scheduled_for <= NOW()`. **Known bug**: SMS channel has no branch — only `if (r.channel === "email" && r.customer_email)` is handled. If channel is `'sms'`, the adapter block is skipped entirely but `UPDATE status='sent'` still fires, silently losing the send. Only email is implemented (via pg-boss)
- **`phase4-polling.js`** — shared long-poll helper for Phase 4 surfaces (KDS, floor plan, booking calendar): `getChangesSince(db, table, since, outletId)`. Returns rows with `updated_at > since`. **Security note**: `table` name is interpolated directly into SQL with no allowlist — callers must never pass untrusted input as the table param
- **`service-tickets.js`** — service/repair ticket lifecycle: `generateTicketNumber`, `createTicket`, `updateTicket`, `getTicket`, `listTickets`, `generateInvoiceFromTicket`, `logActivity`. Auto-generated ticket numbers. Supports activity log and direct invoice generation from a resolved ticket
- **`rental-service.js`** — rental lifecycle: items, assets, contracts, status transitions (`confirmContract`, `checkoutContract`, `returnContract`, `completeContract`, `cancelContract`), availability, overdue detection, invoice generation. Also exports `generateContractNumber`, `computeLateFee`
- **`room-deposits.js`** — gateway pre-auth deposit flow for room bookings: `createDepositPreAuth`, `handleDepositWebhook`, `captureDepositOnCheckout`, `findBookingByIntent`. Works alongside `payment-gateway.js`; captured on guest checkout
- **`room-service.js`** — hotel/room management lifecycle: room types, rooms, rate overrides, availability (`checkRoomAvailability`), bookings (`createBooking` → `confirmBooking` → `checkInBooking` → `checkOutBooking`, `cancelBooking`, `markNoShow`), folios (`openFolio`, `addFolioLine`, `attachSaleToFolio`, `settleFolio`). Also exports `resolveRateForDate`, `calculateStayTotal`
- **`treatment-plan-deposits.js`** — gateway pre-auth deposit flow for treatment plans: `createDepositPreAuth`, `handleDepositWebhook`, `captureDepositOnSettle`, `findPlanByIntent`. Parallel to `room-deposits.js` but settles on plan completion rather than checkout
- **`treatment-plan-service.js`** — clinical treatment plan lifecycle: patient subjects, plans (`createPlan` → `transitionPlanStatus`, `addPlanNote`), sessions (`startSession`, `completeSession`, `markSessionNoShow`, `cancelSession`), charting, lab orders. Also exports `validateStatusTransition`, `calculateSessionCompletionPct`, `generatePlanNumber`, `generateLabOrderNumber`, `logActivity`. Folio sub-system: `upsertFolioForPlan`, `writeSessionFeeLine`, `addFolioLine`, `attachSaleToFolio`, `recalcFolioTotals`, `settleFolio`. Worker-called exports: `getOverduePlans`, `getUpcomingSessionsNeedingReminder`

- **`couriers/`** (16 files) — courier adapter pattern. See `couriers/CLAUDE.md`
- **`marketplace/`** (5 files) — marketplace API clients for integrations hub:
  - `base-marketplace.js` — abstract base class defining interface: `testConnection()`, `syncProducts()`, `pullOrders()`, `pushInventory()` (all throw "Not implemented")
  - `daraz-client.js` — Daraz Seller Center API (Open Platform SDK)
  - `meta-commerce.js` — Facebook/Instagram Commerce API (catalog + orders)
  - `whatsapp-client.js` — WhatsApp Business Cloud API (templates + conversations)
  - `google-merchant.js` — Google Merchant Center Content API (product feed + diagnostics)
